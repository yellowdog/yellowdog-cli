## Live System Tests

`tests/live/` (`--run-live`, marker `live`) provisions real compute from its own configuration (`YDST_CONFIG`, else `~/.config/yellowdog/system-tests.toml`, with `YDST_<SECTION>_<KEY>` overrides; an unknown key is an error, a retired key is listed in `harness/config.py`'s `RETIRED` with its replacement and ignored with a warning, never special-cased; its template is `tests/live/system-tests.example.toml`, which a test holds to `SCHEMA` (a key added to the schema is added there); `make live_config` (`tests/live/check_config.py`) checks it alone, contacting nothing; see `DEVELOPMENT.md`) and depends on nothing outside the repository. Its `[platform]` is the one source of Platform credentials for `--run-system` too: `conftest.py`'s `_use_system_test_credentials()` sets `YD_KEY`, `YD_SECRET` and `YD_URL` from `harness.config.platform_environment()` before the CLI's configuration loads, replacing the shell's, and neither suite reads them from the shell. `tests/live/harness/` is plain Python, shared with `tests/live/sweep.py`. Its rules: everything a run makes is named `ydst-<yymmddhhmm>-<4 base36>-...` and tagged with that run ID; the namespaces are fixed (`harness/run.py`'s `NAMESPACE` and `LIMITED_NAMESPACE`, never configured), shared and never removed; secrets reach `yd` only through its environment (`YD_KEY`, `YD_SECRET`, `YD_VAR_*`, `YD_DATA_CLIENT_REMOTE`), never the generated `config.toml`; every inherited `YD_*` variable is dropped; `yd` is always called with the long `--json` and `--quiet`, and given `--debug` by the harness, its trace split from stderr (`harness/yd.py`'s `split_trace()`, `Result.trace`), checked for secrets with the rest and shown in a failure, so `Result.stderr` holds the CLI's messages alone; and `yd resource create` never with `--validate`, which checks the schema and creates nothing. A second `conftest.py` means `import conftest` is ambiguous, so a test needing the root one loads it by path (`test_system_credentials.py`). The run is owned by `tests/live/live_session.py`, a plugin the root `conftest.py` registers under `--run-live`, since an xdist controller never loads `tests/live/conftest.py`: the controller sets the run up when its paths reach `tests/live` and hands its ID to the workers, which only attach to it; a lone process sets it up on the first live test. `tests/live/test_live_providers.py` chains each provider's steps (`live_chain.py`), and `harness/capabilities.py` records the actions a provider refuses, each held to its refusal, and its known faults (an action the Platform accepts but gets wrong, with the bug raised), each held to its symptom and reported as a `KnownFaultWarning` until it stops occurring. Every `yd` call fails if its output holds a configured secret (`SecretInOutput`), and secret variables are named `secret_<provider>_<key>` so that `yd variables` redacts them. `tests/live/test_live_failures.py` fails on purpose (not found, authentication, permission as a limited Application with `work-viewer` in `yd-cli-tests` alone, connection, timeout): a call made to fail passes `expected_failure=True`, which earns no coverage, and a secret learned mid-run (the limited Application's key and secret, a Configured Worker Pool's token) is registered with `Yd.add_secret()` before its output is checked; an outcome the Platform decides is pinned in `harness/failures.py`'s `PINNED` with its reason. A scenario's clean-up runs in `harness/work.py`'s `cleaned_up()` (`cancelled_after()` for its Work Requirements), never a bare `finally`, so a clean-up failing after the scenario failed is a warning rather than the error reported. A whole-suite session ends with the coverage gate (`harness/coverage.py`): a CLI verb neither exercised nor in `NOT_EXERCISED`, with its reason, fails a session whose tests passed (after a failure it is named, not failed on), so a new verb needs a scenario or a reason; `NOT_EXERCISED` holds only commands with no live scenario (the offline and separately tested ones, and `yd node stop`/`start`/`restart`, since a Worker Pool takes such a node's instance away), which a test pins. Never run it unasked.

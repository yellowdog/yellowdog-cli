## yd-variables redaction

`variables.py` (`yd-variables`) redacts the `key` and `secret` variables, named or not, substituting `REDACTED_VALUE` from `output_style.py` (`resource_creation.py` uses the same constant for a withheld Keyring password). Those two (`SECRET_VARIABLES`) are the only variables in the table the CLI put there itself — `load_config_common()` adds them alongside `url`, `namespace` and `tag` — so they are the only ones that can be *known* to be credentials. It also redacts every other variable whose name matches `SECRET_VARIABLE_NAME_PATTERN` in `variable_syntax.py` (`secret|password|passwd|token|credential|private_key`, case-insensitive, `re.search`), and says so: when at least one was redacted that way, `main()` prints one `print_warning()` line ahead of the JSON giving the count and the pattern and saying everything else is shown in full and `--show-secrets` reports all (so `--quiet` suppresses it with the other warnings). Name-pattern redaction catches identifiers and misses badly-named secrets such as `APP_CREDS`, so as a *silent* heuristic it would read as a guarantee the command cannot keep; this one states what it matched and that nothing else was withheld, so it cannot be read as a guarantee — and `key` alone is left out of the pattern so that `APP_KEY_DEMO`, an identifier, is still shown. A value redacted by the pattern is already `REDACTED_VALUE` by the time the undefined-variable check runs, so it carries no reference to check, and only `key` and `secret` are left out of that check by name. All of the redaction applies to a named variable too, with a line saying `key`/`secret` were redacted when they were named, and `--show-secrets` (the same option name `yd-cloudwizard` uses) is the one way round it: otherwise naming a variable would report it whatever it was, which would let an MCP tool, which can never pass `--show-secrets`, ask for `secret` by name. `report_variables()` returns a `Report` (the variables, and which were redacted as credentials, by the pattern, or by value), so the rules and the notes counting them are decided in one place. `yd-variables` is the one command with `requires_credentials=False` in the registry (`ARGS_PARSER.credentials_required`, which is false for any command under `--validate` too, since checking a specification contacts nothing), so `wrapper.py` loads `[common]` non-strictly for it and it runs, and reports `key`/`secret` as `null`, without an application key or secret; a named variable never defined is warned of, and a name no variable could have is refused as parsed (`check_variable_names`). And `tests/test_variables_command.py` holds the misses (`APP_KEY_DEMO`, `APP_CREDS`) as well as the matches; its `_run()` drops inherited `YD_VAR_*` variables, which would otherwise join every full report and the note's count. A variable whose *value* is, or holds, the configured key or secret (`holds_credential()`: the whole value, or inside it for a credential of `CREDENTIAL_SEARCHED_LENGTH` or more) is redacted too, with a note giving the count, since `leak = "{{secret}}"` is the secret under another name. The one other extension of that limit is structural, not a name guess: the `{{dataClient.remote}}` and `{{dataClient.<profile>.remote}}` variables are the CLI's own too, and an inline rclone connection string carries its credentials in its parameters, which the rclone parser can identify — so the full report renders those through `dataclient.rclone.shown_remote()` (name, type and provider kept, `<N parameters redacted>` for the rest; a named remote unchanged), exactly as `yd-doctor`'s profile rows do, under the same rule: lifted by `--show-secrets` alone. `is_remote_variable()` in `variables.py` is the name test, built from the `dataClient` section and `remote` property constants. The same rendering applies to any variable whose *value* is an inline connection string (`dataclient.rclone.is_inline_remote()`: rclone's `:backend,...` form, or `NAME,...` with a `type` parameter, optionally `rclone:`-prefixed — deliberately strict, since `parse_rclone_config()` reads anything with a comma as a remote and `shown_remote()` would turn `a,b` into `a`), because a user's `remote_with_keys` carries its credentials exactly as `{{dataClient.remote}}` does; for a variable the CLI did not register, `main()` prints a note giving the count (`Report.by_value`), as it does for the name pattern. `shown_remote()` keeps an `rclone:` prefix but withholds a trailing `:path` with the last parameter: it cannot be told from the `:port` of a URL-valued parameter such as `endpoint`, and splitting on the last `:` would show that port in `yd-doctor`'s report.
